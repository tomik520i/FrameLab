What actually reached the picture

The main measure counts the correct meaning at a fixed instant: half a second before each target line ends. Missing captions and an earlier line still on screen count as failures. This measures the whole application, not isolated model language ability.

In this set memory improved the overall result, but reduced success after a topic change. Inspect all three phases; the overall percentage alone is not enough.

Latency includes OCR, queueing, translation and waiting for display. Ordinary memory-off caching was retained; memory-on translates again with context. This affects both speed and quality. Missing outputs are excluded from latency percentiles but remain in failure counts.

What to fix next

All failures from this run are retained. Translation code, model parameters, scene timing and memory were unchanged across the 300 main runs. Any fix needs its own labelled repeat evaluation; a better retry must not replace the original failure.

How this was measured

The actual application path

Burned-in video text → FrameLab decoding → RapidOCR → filtering → selected translator → queue and rendering. No hand-supplied translation or context goes directly to the API. Three framebuffer exports before Present capture the actual rendered picture; the log also records Present success. This does not measure physical panel illumination.

Scenes and order

75 language cases use 50 distinct input videos. Some semantic families repeat across languages. Each 41-second scene contains two setup lines, target A, eight 1.25-second interruptions, target A again, two topic-changing lines and target B. Interruptions include dialogue, a licence plate and a UI label. Case order is pre-shuffled and the four variant orders rotate. Each variant has one main run, not repeated-trial statistics.

What memory means here

The v4 candidate uses the same model for translation and selecting important original lines. It selects cited lines in the background; original wording, rather than invented summary claims, is passed back to translation. Up to eight retained lines are joined by the two latest lines. Old information can still outweigh a new topic. An invalid source reference stops long memory and retains short history; that fallback is logged.

Review without a paid judge

Codex directly reviewed outputs without another judging API call. Provider and mode names are omitted from the candidate file; identical outputs within the same context are reviewed once. Meaning: 2 = fits the situation, 1 = partial, 0 = wrong. Language: 2 = natural, 1 = minor flaw, 0 = unusable. This is qualitative AI review, not an independent native-speaker panel. References are examples, not exact-match requirements. A correct neutral expression may stay identical in both situations.

Hardware and performance

Windows 11, i5-13420H, RTX 4050 Laptop 6 GB and 32 GB RAM. Input 1280 × 720 / 30 FPS, output normally 1920 × 1080 (run 005 exception disclosed below), NVIDIA VFG 2× and experimental NR at 540p, one pass, strength 0.65. The Gemma 4 26B A4B ultra-uncensored-heretic Q5_K_S derivative runs on a separate LAN PC with an RTX 3090 24 GB; gpt-6-luna uses a paid API without thinking. These translation weights therefore do not run on the laptop. Ordinary background applications were not shut down.

Limits of the evidence

These are authored diagnostic dialogues over gameplay, not original GTA conversations or representative accuracy across all games. Rapid interruptions deliberately stress queues. Measured FPS counts application-submitted frames. Exporting an image briefly stalls rendering; measured overhead is disclosed. Network conditions, server load and background applications can affect latency. The feature remains optional and off by default; this study itself does not release a new public installation package.
