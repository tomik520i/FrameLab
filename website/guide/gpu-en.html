AMD Radeon and older GeForce can use the portable FG paths if their hardware/driver meets the backend requirements. No AMD card or older GeForce was physically benchmarked in this release. Intel UHD is tested, but RIFE is too slow on this particular iGPU at 720p. NR is blocked on AMD, Intel, GTX and unknown architectures in the UI, shortcuts, restored sessions and initialization. FrameLab is finished-image video interpolation, not native in-game DLSS 5 integration.

Getting started

Open Frame gen → Computational backend. Choose Optical Flow for a low-power GPU, or RIFE Low / 2× as a first RIFE test. The RIFE ONNX files and DirectML runtime are bundled. Missing files or unsupported hardware disable RIFE with an explanation; there is no hidden CPU execution fallback. Use Start FrameLab - RIFE.cmd for the RIFE demo. --adapter N selects the DXGI adapter for rendering and DirectML. 3× and 4× require two and three inference passes per pair; they can be much slower.

Low changes the motion computation, not the output resolution. The model may take time to compile on first load. Let loading finish before changing settings again.

Translation has its own device selector under Subtitles → Local / offline → Translation compute. See the CUDA, Vulkan and CPU guide. Selecting Vulkan for translation does not enable the NR enhancer on unsupported GPUs.
