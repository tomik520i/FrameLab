# Recording and comparison data

Each `app/recordings/analysis-15s-ID` contains a recording ID and settings ID. `session.json` records GPU, backend, pacing version, source, dimensions, quality, multiplier, automatic cuts, dedup and VSync. Preview.7 records pacing version 3 and `output_scheduler` to distinguish independent GPU work from the diagnostic legacy wait mode. `capture-settings.json` adds RAM strategy, capture rate snapshot and start time. `result.json` distinguishes complete and interrupted takes.

Preview.5 compresses individual RAM blocks losslessly on four worker threads: constant alpha removal and reversible planar byte deltas, then LZ4 when useful. Incompressible blocks retain their exact pixels. No pixel disk writes occur until capture and GPU readbacks finish. Disk BGRA/CSV remains compatible with earlier exporters. The buffer is bounded by available physical RAM minus a 12-GiB system reserve; a full buffer stops the take with a reason. Settings include the budget, rate estimates and compression strategy; results include raw/stored/peak RAM bytes. Admission and disk checks happen before take creation, and start errors remain visible.

`frames.csv` identifies every raw / generated image, source A/B IDs, temporal position, dimensions and byte offsets in top-down BGRA8 files. `presents.csv` contains submission timestamps and image references. References before the recording window are legitimate and must be excluded from pair metrics if their images are absent.

New takes contain `display-confirmations.csv`: observation time, raw/generated image ID, DXGI present ID, refresh counters and QPC timestamp. Each observed OS confirmation is mapped to a known submission; skipped present IDs are never assumed displayed. This yields a sampled lower bound on image-ID changes, not pixel uniqueness or a camera measurement of monitor scanout. Empty data means no confirmations were captured. Take 82183953 predates this measurement and cannot retroactively prove physical monitor FPS.

The exporter creates lossless full-resolution raw / generated FFV1 MKV files, a resized 60-FPS output preview and matched A/generated/B comparison. MKV uses evenly spaced indexed playback; CSV is authoritative for irregular timing. `clips.json` links clip IDs, settings IDs, file hashes and completion state. Preview movies do not prove physical monitor output cadence.

The complete preview.8 package includes an isolated Python/Pillow/FFmpeg environment for clip export. The app prefers `tools/python/python.exe`; minimal/source installations can use system Python and dependencies from `tools/setup-diagnostics.ps1`. Export failures are reported in `export-error.txt`. Optional `tools/audit_analysis_take.py TAKE_DIRECTORY` requires the analysis dependencies and checks every stored frame, creating metrics / visual samples. Pixel differences are not quality scores; true interpolation accuracy requires held-out ground-truth footage.

For a publishable comparison after export and audit, run `tools/build_comparison_materials.py TAKE_DIRECTORY --start 3 --seconds 3 --slowdown 4`, then `tools/finalize_comparison_release.py TAKE_DIRECTORY`. These create source-aligned and recorded-submission movies, native-pixel crops, a crossfade reference, per-preview-frame ID mappings, full-decode validation, SHA-256 manifests and a compact release ZIP. The original recording stays untouched. `comparison_crops.py` derives in-bounds native crop coordinates from the input resolution; review the chosen regions visually for each scene. Use `build_phase_strip.py` to show every saved phase of one pair and `build_readme_gif.py --recording-id ID --source-start SECONDS` for a six-times-slower README GIF from the verified movie.
